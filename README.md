# Pocket Plans

Кукунин Вячеслав Борисович · Б9123-09.03.02прс

Финальный проект второго семестра: персональный планировщик покупок на Kotlin.
Каталог DummyJSON — источник контента; собственная ценность приложения — списки,
бюджеты, заметки, целевые цены и сохранённые поисковые сценарии.

## Основа и финальное расширение

ДЗ №3–6 реализованы заново: выполненной базы второго семестра не было.
Это не порт принятой комиссионной работы: присланный Flutter-архив содержал шаблон
со счётчиком. Разрешение преподавателя на Flutter не обязывает его использовать;
здесь выбран Kotlin и стек из ТЗ. Не утверждается, что базовые ДЗ ранее сдавались.

База: Compose Material3, Navigation `catalog` → `detail/{id}`, Retrofit suspend API,
Repository, Hilt, Room, ViewModel/viewModelScope, Loading / Error+Retry / Empty / Success.
Данные Room и настройки DataStore реактивно влияют на UI.

Финальное расширение включает четыре законченных сценария:

1. **План покупки с бюджетом.** Создать/изменить список, добавить товары из карточек,
   менять количество, видеть сумму и превышение бюджета, отмечать купленное и видеть
   оставшуюся сумму. Повторное добавление увеличивает количество без дубля. Удаление
   списка удаляет его связи, но сохраняет каталог и другие списки.
2. **Личный выбор и отслеживание цены.** Сохранить заметку, целевую цену и избранное;
   в разделе «Моё» видеть достижение цели; в карточке видеть историю изменения цены;
   добавить выбранный товар в список. Обновления не стирают личные решения. Цель и
   заметку можно очистить. История хранит до 30 обнаруженных изменений на товар.
3. **Сохранённые фильтры.** Настроить запрос, категорию и избранное, сохранить
   именованный пресет, перезапустить приложение и применить его к актуальному кэшу.
   Пресеты можно переименовать и удалить; новые условия сохраняются из каталога.
4. **Подготовка офлайна.** Запустить обновление через WorkManager, наблюдать ожидание
   сети/выполнение/результат, затем пользоваться карточками и личными данными без сети.
   Настройки управляют TTL и периодическим обновлением.

Первые два сценария проходят через несколько слоёв и сущностей. Финальное расширение
не ограничивается темой и избранным. Локальные профили из необязательного раздела 3 ТЗ
не реализованы: приложение однопользовательское, без серверной авторизации.

## Локальная модель

| Room-таблица | Данные и поведение |
|---|---|
| products | Полные текстовые карточки API, цена в целых центах, дата обновления |
| personal | Заметка, цель, избранное; внешний ключ на товар |
| plans | Именованный список, бюджет, дата создания |
| entries | Связь списка и товара, количество 1–999, статус покупки |
| history | Последний просмотр товара без дублей |
| presets | Именованный запрос + категория + режим избранного |
| price_points | История изменения цены, связь с товаром |
| sync_meta | Дата полностью успешной синхронизации |

DataStore хранит **только** настройки: тему, сортировку, фоновые обновления, TTL.
Деньги — целые центы; ввод проверяется через BigDecimal без ошибок Float/Double.
Названия ограничены 80 символами, заметки — 2000.

## Offline-first и WorkManager

UI получает каталог из Room. Сеть обновляет БД: все страницы API сначала загружаются,
затем записываются одной транзакцией. Ошибка на любой странице сохраняет прежний кэш
и время последней успешной синхронизации. `@Upsert` сохраняет личные связи; удалённые
с API товары остаются в кэше ради пользовательских списков, дата видна в карточке.

Уникальная периодическая задача примерно раз в час при наличии сети проверяет TTL
(1, 6 или 24 часа). Свежий кэш не обновляется. Явная подготовка офлайна обходит TTL
и работает при выключенной периодике. Временные ошибки получают retry с exponential
backoff; после 5 неудачных попыток задача завершается ошибкой. Время запуска определяет
Android. CancellationException пробрасывается, Mutex защищает параллельные refresh.

Без первой загрузки каталог пуст и нужен интернет. После загрузки карточки, заметки,
списки, фильтры и история работают без сети и после перезапуска. Изображения не
используются — весь контент карточки кэшируется. Личные данные не отправляются на сервер.
Удаление приложения удаляет локальные данные, резервное копирование отключено.

## Реактивность

`CatalogModel` объединяет независимые query (debounce 300 ms), category, favorites,
Room products, Room personal, DataStore preferences и sync status. Используются
combine, debounce, distinctUntilChanged, map, collectLatest, stateIn.
StateFlow хранит длительное состояние, SharedFlow передаёт refresh/retry-действия;
новое действие отменяет устаревший запрос. Настройки также реактивно управляют
планировщиком, а WorkManager отдаёт статус подготовки офлайна через Flow.
